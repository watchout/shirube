## Technical Design

One entry file `templates/adoption/README.md` is the kit (AK-01). It is a checklist table with **eight rows, one per item**; every row has a `state` cell that starts as `<unfilled>` and a `ref` cell that must hold a URL (an adoption record, a template, or a decision) — the kit never restates a decision, it links it (AK-01, AK-05). Unfilled cells stay literally visible (AK-02). Three rules live as three lines under the table (AK-05 adoption record, AK-06 ID prefix check, AK-07 one table per classification). Two small templates sit next to it (daily comment AK-09, goal-tree map AK-10). The audit v1 checklist moves into this repository as `docs/audit/sds-audit-v1-source-checklist.md` and becomes the canonical copy (AK-04); the iyasaka-arc file is replaced by a one-line pointer after merge. **The kit is these four files and they share one 150-line budget** (AK-08; v2 — v1 wrongly left the checklist outside the budget). The hygiene profile skeleton is **not** a fifth file: row 1 links the existing `templates/hygiene-profile.md` (36 lines on main [検証済]). Alternative not taken: one big document per item — rejected because the checklist must be the single classification table (AK-07) and the budget is 150 lines.

## Data / API / Contract Impact

- No workflow, script, config or threshold change. The reusable workflow and the profile format are unchanged.
- **Filling contract (v2, AK-GATE-003)** — the **table is the authority; the YAML block is a projection of it**, so the classification lives in one place (AK-07):
  - rows are identified by the fixed keys `i1`…`i8` in table order; columns = `key`, `item`, `state`, `ref`; `state` ∈ {`<unfilled>`, `filled`}; `ref` = one URL (row i6 may append `prefix: <chosen>`), or `<unfilled>`;
  - a row counts as filled **only when** `state = filled` **and** `ref` is a URL; `filled` with `ref = <unfilled>` (or the reverse) counts as unfilled;
  - `sds_adoption:` = `repo`, `kit_version` (the tag), `items_filled` (the keys of the rows that count as filled, in table order), `id_prefix` (row i6's prefix or `<unfilled>`), `adoption_refs` (the URLs of those rows, same order);
  - the reader (the auditor now, W6 later) **recomputes `items_filled` from the table**; any difference from the YAML (e.g., table 7 filled, YAML 8) = **mismatch** → the repository counts as not filled until the YAML is regenerated from the table. The seat edits the table, then copies; it never edits the YAML alone.
- The goal-tree template refers to the stage names by URL (standards map §1) instead of restating them (AK-07).
