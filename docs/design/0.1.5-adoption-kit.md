## Technical Design

One entry file `templates/adoption/README.md` is the kit (AK-01). It is a checklist table with **eight rows, one per item**; every row has a `state` cell that starts as `<unfilled>` and a `ref` cell that must hold a URL (an adoption record, a template, or a decision) — the kit never restates a decision, it links it (AK-01, AK-05). Unfilled cells stay literally visible (AK-02). Three rules live as three lines under the table (AK-05 adoption record, AK-06 ID prefix check, AK-07 one table per classification). Two small templates sit next to it (daily comment AK-09, goal-tree map AK-10). The audit v1 checklist moves into this repository as `docs/audit/sds-audit-v1-source-checklist.md` and becomes the canonical copy (AK-04); the iyasaka-arc file is replaced by a one-line pointer after merge. Alternative not taken: one big document per item — rejected because the checklist must be the single classification table (AK-07) and the budget is 150 lines (AK-08).
