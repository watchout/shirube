## Technical Design

Each check step gets an `id` and `if: ${{ !cancelled() && steps.refs.outcome == 'success' }}`; PR size and Python
keep their own condition appended. GitHub then runs a step even after an earlier step failed, while the job result
stays failure [文献確認: GitHub Actions expressions `cancelled()` and step `outcome`]. A final `always()` step reads
`steps.<id>.outcome` for all 12 checks, prints them to the step summary and exits 1 on any failed / cancelled /
unexpectedly skipped check. No script changes; no new input or output on the reusable workflow.

Alternative not taken: `continue-on-error: true` on each check plus an aggregate step — GitHub then reports a failed
step as success and the S8 contract test forbids the keyword (ADR-002 decision 4).
