## Who and what improves (Working Backwards, SRC-M-01)

- user: the operator of a consumer repository that calls `hygiene.yml` (first: agent-comms-mcp, `mode: report_only`)
  and the seats that read its run (suite-lead, devauditor).
- the change they notice: one run shows the outcome of every check. Today one failing check leaves every later check
  SKIPPED [検証済: agent-comms-mcp#980 run 36524256657 — lines-baseline FAIL with 103 files, the eight later checks
  SKIPPED; aun agent-comms-mcp#977 5884009062], so the run says nothing about duplication, unused code, dependency
  direction, structure, guards, secrets or PR size.
- success measure: checks with an outcome per run = 12 (python counted as `skipped` when off), whatever the number of
  failures. Measured on the first consumer run after its pin moves to 0.1.4 [推測: not yet observed on a consumer].
- burden measure: reruns needed to see every result, from "one per check fixed in turn" to 1. Reading: the last step
  prints one `check=outcome` line per check into the step summary.
- out of scope: reading `mode: report_only` inside W1 (W1 does not read the profile mode [文献確認: switch plan v2.6
  §1]; the job still fails on any failure); baselines for existing excess (0.2.0, owner D0); registering the check as
  required (owner D3); the consumer's own workflow change (its pin bump).
- important FAQ / open questions (kept even if the page grows):
  - Why not `continue-on-error`? GitHub would then report the failed step as success in the job result; S8 and the
    contract test forbid it [文献確認: tests/workflow-contract.test.mjs "workflows hide no failures (S8)"].
  - Does the job still fail? Yes, exactly when it failed before, and additionally when a check went missing.
  - Why a last step? One place lists all outcomes and it fails on failed / cancelled / unexpectedly skipped, so a green
    job can never hide a missing check.
  - Open: the "run after failure" path is not observable in this repository (its own checks pass [検証済: run
    36527824537]). The first observation is the consumer run after the pin bump; acceptance A3 stays NOT_RUN until then.

## Requirements (EARS)

| ID | requirement | pattern |
|---|---|---|
| R17 | When a check fails, the workflow shall still run every later check and shall fail the job. | event |
| R17a | The workflow shall not use `continue-on-error` on any step. | ubiquitous |
| R17b | While setup (checkout, install, refs) has not succeeded, the checks shall be skipped and the job shall fail at the setup step. | state |
| R17c | The last step shall list every check's outcome and shall fail if any of the nine unconditional checks is not `success`, if neither PR-size step is `success`, or if Python is neither `success` nor `skipped`. | ubiquitous |
| R17d | If a check step is cancelled, then the last step shall fail (cancelled is never a pass). | unwanted |

## Design (one paragraph) and decision

Each check step gets an `id` and `if: ${{ !cancelled() && steps.refs.outcome == 'success' }}`; PR size and Python
keep their own condition appended. GitHub then runs the step even after an earlier step failed, and the job result is
still failure [文献確認: GitHub Actions expressions `cancelled()` / step `outcome`]. A final `always()` step reads
`steps.<id>.outcome` for all 12 checks, prints them to the step summary and exits 1 on any failed / cancelled /
unexpectedly skipped check. No script changes. The decision and the alternative not taken are ADR-002.

## Protected surfaces and failure handling

- protected surfaces touched: none in this repository (the reusable workflow is code; consumers pin a commit). A
  consumer's pin bump is that consumer's workflow change and follows its own owner rule.
- failure → detection → containment → recovery:
  - setup failure → `refs` skipped → every check skipped (R17b) → job red at the setup step → fix setup, rerun.
  - check failure → that step red, later checks still run → job red with the full list → fix, or baseline (0.2.0).
  - missing outcome (a check skipped although setup succeeded) → last step exits 1 → inspect which check has no outcome.
