## Q1. [順] 「端から端まで動く最小の版」は、どの単位に付けるか

私たちの決まりは「最初に端から端まで動く最小の版を作り、実物で確かめてから機能を足す」です。AI-DLC は、単位の一覧の先頭の単位をその最小の版として扱い、その単位が終わるときに、実物の確かめと人の確認を求めます。一覧の先頭にある単位が、そのまま最小の版になります。

arc の答えは U1（Shirube の ci の concurrency）を最初にです。U1 は `ci.yml` だけの小さな変更で、網羅率の門は含みません。今の一覧は U1 が先頭なので、そのままだと最小の版の確認は U1 に付きます。U1 の確認は「同じ PR の古い実行が取り消される」までで、網羅率の門が端から端まで動くことは確かめません。

たとえば先頭を U1 のままにすると、U1 が終わるときの確認は Shirube 自身の CI の実行で見えます。網羅率の門が端から端まで動くかは、U3 が終わるときの確認で見ることになります。先頭を U3 に直すと、最小の版の確認は網羅率の門そのものに付きますが、S10 を最初に置く順とは食い違い、他の取り組みが待つ kit の版が遅れます。

- A. 先頭は U1 のままにする。最小の版の確認は U1 に付き、確かめは Shirube 自身の CI の実行（`npm test` と、PR の CI の実行で古い実行が取り消されること）。網羅率の門が端から端まで動くことは、U3 の完了の確認として U3 の設計で定める（AI-DLC の最小の版の確認とは別）
- B. 一覧の先頭を U3 に直す（単位の一覧と依存の記録を直す）。最小の版の確認は U3 に付き、網羅率の門を command として端から端まで動かして確かめる。U1・U2 は U3 の次に作る。範囲の文書の「S10 を最初に置く」と arc の答えとは食い違う
