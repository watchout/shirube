## Q3. [判定] 「必須の試験」をどう決めるか

測定を落とす条件の 1 つに、必須の試験が流れていない（NOT_RUN）があります（指定の要件 6）。決めたいのは、何を「必須の試験」とするかを、誰がどこで決めるかです。
たとえば、ある repo に試験ファイルが 20 本あり、うち 2 本が DB を要するため通常の CI では流さないとします。20 本すべてを必須にすると、DB を要する 2 本は常に NOT_RUN になってしまいます。

- A. 呼ぶ側が、必須の試験を入力で名指しする（名指しされたものが流れていなければ NOT_RUN）
- B. 追跡されている試験ファイルすべてを必須とし、流さない物は理由つきの除外で名指しする
- C. 設計の段で決める
- X. Other (please specify)

[Answer]: B（arc の答え。Owner の委任 iyasaka-arc#49 6762288830。Owner の言葉ではない。追跡されている試験 file をすべて必須とし、流さない物は理由つきの除外で名指しする。新しい試験 file が黙って必須から外れないため）

## Q4. [判定] 除外の単位

DB を要する試験とその対象ソースは、「DB の job で測る」か「理由つきの除外」にできます。除外は入力で名指しし、理由を出力に残し、呼ぶ側の上書きで広げられません（指定の要件 4）。決めたいのは、名指しできる単位です。
たとえば、ディレクトリ名や `*` を含む指定を許すと、1 行書くだけで多くのソースが分母から外れます。ファイルを 1 本ずつ名指しする形なら、除外が増えたことが差分で見えます。

- A. ファイルを 1 本ずつ名指しする形だけ許す（ディレクトリ・ワイルドカードは不可）
- B. ディレクトリ単位までは許す（ワイルドカードは不可）
- C. 設計の段で決める
- X. Other (please specify)

[Answer]: A（arc の答え。Owner の委任 iyasaka-arc#49 6762288830。Owner の言葉ではない。file を 1 本ずつ名指し。ディレクトリ・ワイルドカードは不可。除外が差分で見えるため）

URL の形が正しいだけの確かめなら、実在しない URL を書いても通ってしまいます。実在と本文の一致まで確かめるには、GitHub の読み取りが要り、そのための資格情報の扱いも決める必要があります（社内標準 S9: 用途ごとに最小）。

- C. 設計の段で決める
- X. Other (please specify)

[Answer]: A（arc の答え。Owner の委任 iyasaka-arc#49 6762288830。Owner の言葉ではない。形の確かめだけ: 決定の URL の形・値・根拠がそろうこと。実在と本文の一致は監査が確かめる。門に読み取りの資格情報を持たせると守る物（資格情報）に触れるため。出力に、名指された URL と主張された値を必ず残し、監査が照らせるようにする）

- D. 初版は notice と job summary だけ（機械が読める形は次の版）
- X. Other (please specify)
