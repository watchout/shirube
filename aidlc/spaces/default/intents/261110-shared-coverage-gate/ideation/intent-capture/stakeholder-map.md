# 共有の網羅率の門 — 利用者と関係者

## Key Stakeholders

| 関係者 | 関心・担当 | Source |
|---|---|---|
| 社内製品の開発・CI担当 | 各製品で共用できる網羅率の門を使い、重複する計測・判定の仕組みを減らす | [Q1] [Q5] |
| Owner | 取り組みの範囲と保護対象を判断する | [Q5] |
| arc | 設計の持ち主として既存の分担に従う | [Q5] |
| Shirubeの席 | 共有の門を作成する | [Q5] |
| arc-sec | 導入前に新しい依存の安全を確認する | [Q1] [Q5] |
| devauditor | 作成した成果の独立監査を行う | [Q5] |
| suite-lead | 作者と別の既存担当として統合を行う | [Q5] |

## Decision-makers and Influencers

| 判断・確認の対象 | 担当と境界 | Source |
|---|---|---|
| 目的・初版の範囲 | Ownerが判断する。指定9項目すべてを目的にし、初版は架空の利用例の検証までとする | [Q1] [Q2] [Q3] [Q4] [Q5] |
| 設計と作成 | arcが設計の持ち主、Shirubeの席が作成という既存分担を使う | [Q5] |
| 新依存の採用 | arc-secの安全確認とOwnerの決定を導入前に通す | [Q1] [Q5] |
| 独立監査と統合 | devauditorの独立監査、suite-leadの統合という既存分担を維持する | [Q5] |
| workflow・利用先CIなどの変更 | 目的や段の確認とは別に、保護対象に必要なOwnerの承認を得る | [Q4] [Q5] |
| 利用先への適用 | 初版の架空の利用例の検証と分け、別途判断・承認する | [Q2] [Q3] [Q4] |

この関係者の整理は、新しい担当への連絡、委任、依存の導入、workflowや利用先CIの変更を実行した記録ではない。既存の担当と判断の境界を引き継ぐ。[Q1] [Q4] [Q5]

## Communication Requirements

| 共有するもの | 場所と扱い | Source |
|---|---|---|
| Ownerの判断が必要な事項 | この会話で確認する | [Q6] |
| 成果・試験・独立監査結果 | Shirubeの正式な取り組みの記録と単位PRで追える形にする | [Q6] |
| 追加の定例報告 | 設けない | [Q6] |
| 公開する資料・試験データ | 秘密・非公開資料・元repoのコードを出さず、試験データは架空だけにする | [Q1] [Q6] |
| 既存U1との関係 | 新しい取り組みの開始を理由に既存U1の作業を中止・変更しない | [desc] [Q4] |
