# 安全の要件（audit-intake-extra）

> 単位 = この取り組みの全体 1 つ、components = 今の checker の受付の file。受付は「照らされていない code が検査を通った」ことを成功と読まないための道具で、この取り組みはその判定に「宣言した追加の checkout」を足す。広げても失ってはならない性質を、ここに固定する。認証・認可の仕組みを新しく持たない（受付が使う GitHub の読み取りの資格は今のまま）。

## 上流

- requirements: `aidlc/spaces/default/intents/261113-audit-intake-extra/inception/requirements-analysis/requirements.md`（NFR1・NFR8・NFR9、FR1・FR2、Assumptions A1〜A5）。
- functional-design: `aidlc/spaces/default/intents/261113-audit-intake-extra/construction/functional-design/rules.md`（BR1.1〜BR3.7）、`functional-spec.md` D2・D6・D7。

## 要件

| ID | 要件 | 測り方 |
|---|---|---|
| NFR1.1 | 失敗は拒否にする（fail closed）。依頼の読み違い・job の記録の欠落・GitHub の応答の失敗・期限切れ・読めない形・不一致は、すべて拒否で、成功に読み替えない（S5・S8） | 各負例（FR4.1）が拒否になること。`try` で例外を飲み込んで続ける分岐を足さないこと（差分の確認と、拒否の経路の試験） |
| NFR1.2 | 観測できなかった実在を成功に数えない。応答が取れない・404・期限切れ・本体が読めない・宣言の repo が受付の資格で読めない、はどれも「観測できず」で拒否 | 差し込みの `api` が例外・空・別の sha・読めない形を返す 4 つの負例で拒否になること |
| NFR1.3 | commit の一致は 40 桁の全桁一致。短縮・前方一致・大文字を一致とみなさない。宣言の repo の綴りは、GitHub の問い合わせの path を作る前に `owner/name` の形で検査し、`..`・`.`・区切りの余り・空・余分な `/`・`?`・`#` を含む綴りは拒否する | 1 桁だけ違う commit・短縮・大文字・`..`・余分な `/` を含む repo の負例が、問い合わせの前に（または全桁一致でなく）拒否になること |
| NFR1.4 | 宣言は証拠ではない（S5）。受け入れの根拠は、job の記録から観測した commit と、問い合わせで観測した実在だけで、依頼の値をそのまま写した値を観測として扱わない。受付の出力に宣言の値を載せない（D7） | 宣言の値を 1 桁書き換えた入力が、観測の側の値（job の記録・応答）と食い違って拒否になること。受理した出力が、宣言なしの出力と同じ形であること |
| NFR1.8 | 宣言を使って、統合の版の数え方を外れない。宣言の commit が依頼の base か head そのもの、または両親のどれかが base か head である宣言は拒否する（BR3.7）。同じ両親を持つ統合の版が 2 つあり、片方を別の repo の commit として宣言しても、通らない。判定は実在の観測（NFR1.2）と同じ応答から読み、問い合わせを足さない | 同じ両親（base・head）で木の違う統合の版が 2 つ、うち 1 つを別の repo の宣言に入れ、job の記録にその両方が出る依頼が拒否になること（宣言ありの対象の job 単位と、2 つの job に分かれた形の両方）。宣言の commit が base／head そのものの負例、両親の片方だけが base／head の負例、両親が読めない応答の負例（実在でなく観測できず）が拒否になること。親が無関係な正例が通ること。理由が `Declared extra checkout derives from requested base/head` と一致すること。記録する `api` の呼び出し数が宣言 1 件あたり 1 のままであること |
| NFR1.5 | 依頼全体を拒否する。一部の対象・一部の宣言だけを受ける形を作らない（BR3.4）。再観測（返却の確認で、証拠を読んだ後に行う観測）が最初の観測と食い違えば拒否 | 2 つの対象のうち 1 つの宣言だけが不正な依頼が、全体として拒否になること。再観測で応答が変わる入力が拒否になること |
| NFR8.1 | 拒否の理由は固定の文だけ。宣言の repo・commit、GitHub の応答の本文、job の記録の中身、token を理由・出力に載せない（BR3.6） | 理由の文字列が、実装の固定の文の一覧のどれかと完全一致すること（宣言の値を含む文字列を連結していないこと）。宣言に合成の token 風の文字列を入れた負例で、出力にその文字列が現れないこと |
| NFR8.2 | 試験の fixture は架空の repo 名と架空の commit だけにする。実在の非公開 repo の名前・commit・資格を置かない。`token: "12 桁の英数字"` の形を置かない（gitleaks が拾う） | gitleaks の検査（CI）が通ること。fixture の repo 名がすべて架空の名前の一覧に含まれること |
| NFR8.3 | 新しい資格情報・権限を要さない。宣言の実在の確認は、今の `api` の差し込み（`gh api`）が読める範囲で行い、読めなければ拒否（S9。A3） | 実装の差分が新しい環境変数・token・権限の取得を含まないこと |
| NFR9.1 | 守る物を変えない。`.github/workflows`・必須の検査・branch protection・契約 `.v2`・hygiene profile の上限・DB の構造・資格情報・本番・料金を、この取り組みの PR で変更しない | PR の `changed_paths` にそれらが含まれないこと（含まれれば保護対象の手続きに戻る） |
| NFR9.2 | 判定の全部を `scripts/hygiene/audit-admission.mjs` の 1 file に収める。依頼の `verifier_sha256` はこの 1 file の bytes に結ばれるので、判定の一部を別の file に出さない（D2。照らされていない code が判定しない） | 差分で、判定に関わる新しい file が `scripts/` に無いこと。import が Node 組込みと `./lib.mjs` だけであること |
| NFR9.3 | この取り組みは R3。PR は `risk:R3` と `json sds-pr` を持ち、統合の前に Owner の exact-head（arc 経由）、統合は作者以外の suite-lead（チームの決まり） | PR の label・本文・Owner の対象 head の承認の URL（本文 SHA-256 つき） |

## 脅威の見取り図（KY の先回りの入口）

「困る大きさ」は社内の決まり（版 11）の表に従う。ここは設計の段の見取りで、先回りの点検（devsecops・architecture-reviewer）が、組み合わせを 1 つずつ表に当てる。

| # | 場面 | 守りの要件 | 残る前提（受付が保証しないこと） |
|---|---|---|---|
| T1 | 作者が、実在する別の repo の commit を宣言し、job が本当にそれを checkout している | NFR1.2・NFR1.4（完全一致と実在だけを照らす） | 宣言した repo・commit の中身の妥当性は照らさない。受けるか差し戻すかは独立の監査の席が宣言を見て決める（BR4.2 の「保証しないこと」） |
| T2 | 宣言の commit が統合の版の commit と同じ | BR2.2（候補が 0 件で拒否） | なし |
| T8 | 同じ両親（base・head）で木の違う統合の版が 2 つあり、片方を宣言の側に入れて候補の数え方から外す（設計監査 1 回目の F01） | NFR1.8・BR3.7（宣言の commit か両親が base／head に由来すれば拒否）。2 つとも宣言に無ければ BR2.2 が 2 件以上で拒否 | 宣言の repo の commit の木の中身は照らさない（T1）。base／head を親に持つ別の枝の commit は宣言できない（fork が同じ object を持つ形も同じ。安全側の取り決め） |
| T3 | 宣言の repo の綴りに path の細工（`..`・`/`・`?`）を入れ、別の API の path を読ませる | NFR1.3（問い合わせの前に形で拒否） | なし |
| T4 | 宣言を大量に入れ、問い合わせを増やす | FR1.5・NFR5.2・NFR5.5（4 件まで。超過は問い合わせの前に拒否） | 対象の数 T には上限が無い（今のまま）。足す問い合わせは T に線形で有界 |
| T5 | 宣言の repo を PR 自身の repo にして、大文字小文字で逃れる | BR1.6（大文字小文字を区別せずに拒否） | なし |
| T6 | 古い checker（中継の固定の版）が新しい欄を無視する | 拒否側に倒れる（今と同じ拒否。NFR2.3） | 中継の版を替えるまでは 2 checkout の PR は通らない（要件の Open questions に記録済み） |
| T7 | 宣言の repo が非公開で、受付の資格で読めない | NFR1.2・NFR8.3（観測できず＝拒否） | 実機の確かめ（MoteNashi）の前に arc か CTO が読めることを確かめる（要件の Open questions） |
