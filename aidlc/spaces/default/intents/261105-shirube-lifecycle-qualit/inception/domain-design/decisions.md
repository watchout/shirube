# Shirube — Domain Designの設計判断

## Sources and Decision Scope

[確認済みの設計計画](domain-design-questions.md)を、[components.md](components.md)の7部品・10データ・呼出依存へ具体化した判断を記録する。要件は[全13Must・47下位FR・10NFR](../requirements-analysis/requirements.md)、受入は[17ストーリー・88AC](../user-stories/stories.md)、実践は[team-practices.md](../practices-discovery/team-practices.md)を保持する。

[CodeKB](../../../../codekb/shirube/architecture.md)のroot `62ff73db52ce8f29f3b982507b5d2e36578ae60f`と別観測main `7e775afd5b755e51e55e269d8dc35b09d180c33e`は異なる。部品の存在や文書の対応を実行合格とせず、合算した完成実装を前提にしない。これらのADRは技術stack、配置方式、保存DB/schema、新API/コマンド、正式Unit/DAG、実装順、保護対象への具体的許可を決めない。

## ADR-001: 信頼境界と変更理由に沿う7部品

### Context

対話、実物の観測、正規AI-DLCへの接続、判定、CI検査の実行、配布、停止制御は変更理由が異なる。初回の小さな確認表示だけへまとめると、後続の実追加・AUN配布でLLM入力と実事実や判定意味を混ぜやすい。既存コードには核とI/Oの分離があり、未知の汎用frameworkを先に作る必要はない。関連はFR1〜FR13、NFR3・NFR5・NFR8・NFR9。

### Decision

確認済み案AのDialogueExperience、NativeAIDLCConnection、EvidenceCollection、ConformanceGate、SensorVerification、KitDistribution、SafeOperationControlを採用する。各データはその責任部品だけが所有し、他部品は観測や結果を参照する。呼出依存はcomponents.mdの12辺とし、下位から上位へ呼び返す循環を作らない。

論理呼出しは明示入力と結果の受渡しとしてsyncで表す。別package/process/networkへの分離は要求しない。LLM共通の意味を保ち、最初の実証環境と他CLIの動作保証を区別する。既存の部品を全部改名・分割する計画へは広げない。

### Consequences

- 対話先や原本取得方式が変わっても、判定規則や証拠の意味を複製しにくい。7部品と10データの所有境界を機械と人の両方で照合できる。
- 観測・対象参照を受け渡す負担が増える。実責任の無いproxyや未確定の汎用抽象を追加せず、既存の核を具体的に使う。
- 配置単位は後続でまとめられる。将来同じ変更理由しか無い境界は再評価できるため、7という数自体を固定の製品要件にしない。

### Alternatives Rejected

- **案B: 対話/正規接続/観測を一つ、判定/検査を一つにまとめる。** 初期の受渡しは少ないが、入力と事実、手元とCI、検査実行と判定の境界を後から分け直す負担が大きい。
- **利用先やLLMごとに全機能を分岐する。** 対応環境ごとの実装は単純でも、同じ規則・理由・証拠意味の独立実装が増える。adapterは輸送と表示の変換へ限定する。

## ADR-002: 正式AI-DLCの状態と権限原本を所有しない

### Context

Shirubeは導入・設定からゴールと継続開発をつなぐが、段・単位・承認を再実装すると進行元が二つになる。既存progression-coreや旧stage/plan関連は、現在の正式AI-DLCの進行を証明しない。古いcursorや別対象、導入承認の流用も拒否する必要がある。関連はFR3・FR4・FR7.3・FR8.3、US1.4・US2.1・US3.1。

### Decision

NativeAIDLCConnectionは現在の正式対象と版と正規操作を観測へ結び、明示開始と必要条件を確認して正規入口へ運ぶ。操作の実行直前と正当な再開時には対象・設定・根拠を再確認する。正式AI-DLCを唯一の段/単位進行元とする。

AI-DLCのstate、段/単位、レビューと承認、GitHubの公開Owner決定・PR・監査は外部所有の原本である。ShirubeはConfigurationDraft、NativeOperation、ObservedSnapshot等の自らの案・操作記述・観測を持つ。準備済み、設定回答、選択、前ゴール完了は開始・段承認・実装計画・保護変更の許可を兼ねない。

### Consequences

- 正規の段順と1単位1PRを保ち、前単位の統合を観測するまで次単位のCode Generationを通さない。Shirubeの機械合格は進行権限を発行しない。
- 正式engineの入口・版の適合が必要になる。main-engine-judgeのClaude/Bun/特定版前提は完成したCodex接続として使えない。
- 正規入口の形式、対象の結び付け、再確認から操作までの変更検知はContract Designの契約で具体化する。接続不能なら依存操作を停止する。

### Alternatives Rejected

- **Shirubeに段/単位の状態を複製し、独自の次操作を決めさせる。** 表示や切替は容易だが正本が競合する。外部状態のsnapshotは持てても進行権限は所有しない。
- **旧stage/plan-binding/道筋受付を正規入口の代わりにする。** 既存コードは使えるが退役した進め方と判定4/5を復活させるため採用しない。

## ADR-003: 原本・観測・公開用記録を分け、真正性の不足を隠さない

### Context

単位PRには必要な記録と承認を含めるが、audit/と.aidlc-engine/、秘密、他repo非公開記録は含めない。READY文字列や作者の任意JSON、原本不明な再生成一致は、実発行元と現在の成果物への正式な承認を証明しない。main-approval-recordはidentityCheck:noneであり、この不足が実在する。関連はFR5・FR9・FR11・FR13.4、NFR2〜NFR5。

### Decision

EvidenceCollectionがObservedSnapshotとPublishedRecordProjectionを所有し、外部原本そのものの所有権・権限は取り込まない。出典・実発行元の観測・対象・版・内容と取得不能を区別する。現在の原本から必要部分を取り出し、別途読んだPRの実内容とConformanceGateで照合する。digestは観測した内容から計算し、desired値やLLM宣言を観測へ写さない。

最初の単位のInceptionを含む必要集合、内部記録の掲載0、公開境界を保持する。必要な公開Owner判断は具体的な原本URLと本文SHA-256を別に確かめる。機械記録の発行元確認とOwner権限を混同しない。

### Consequences

- 公開PRの監査可能性と内部記録の除外を両立させる責任が明確になる。観測不能や改変・旧対象・矛盾した重複を真正な証拠としない。
- **未検証の接続が残る。** CIが内部ログ公開なしで、正式レビュー/承認の実発行元と現在原本を独立確認する既存取得経路はまだ立証されていない。単なる再生成一致では成立しない。
- Contract Designで原本取得・認可された経路・実発行元・現在対象/内容/試行・公開射影・再照合・競合/不明形式を具体化する。成立しないなら依存するREADY/承認条件は停止のままとし、具体案と必要なOwner判断を戻す。新しい署名者・台帳・サービス・DB・権限制度を暗黙に足さない。

### Alternatives Rejected

- **内部ログをそのままPRへ載せる。** 手元との比較は容易でも明示的な除外と公開境界に反する。公開が真正性の証明になるわけでもない。
- **作者生成のJSON、任意の署名、同じdigestだけを信頼する。** 実装量は少ないが発行元や原本の自己申告を循環して確認するだけになる。新信頼元の採択なしに真正性の穴を埋めない。
- **公開用記録だけを新しい承認正本にする。** CIから参照しやすくても、正式AI-DLCの承認や必要な公開Owner決定を置換してしまう。

## ADR-004: 一つの照合核と信頼版のセンサー実行を分ける

### Context

手元の設定でtraceability/upstream-coverageを弱められると、記録不足がPRで通る。I/Oと判定を混ぜると同義入力の意味や再現性も失われる。既存gate1〜3/audit-admission/衛生検査とmain-unit-doneの核には再利用余地があるが、collector/実統合や新4項目の確認は未完成である。関連はFR4〜FR6・FR9〜FR12、NFR1〜NFR6・NFR10。

### Decision

ConformanceGateの外側で観測・検査結果を集め、純粋な核へ適用条件、実観測、結果、時刻、識別子等を明示入力する。核は外部状態や時計や乱数を自分で取得せず、同じ規則・理由・証拠の意味を一箇所で所有する。結果は必要条件の判定であり、進行やOwner権限の付与ではない。

SensorVerificationは信頼する固定版から2センサーと必須集合/severity/対象pathを解決してPR記録へ再実行する。PRは検査入力であり、検査正本や命令ではない。センサーの検査意味は再実装しない。ConformanceGateが対応する実行元・版・PR/head・入力と実結果、および必要条件を確認する。

4分類の設計監査、同PRの設計だけのheadと実装前の順序、設計変更による旧保証の失効、実装headの新しいCI/独立監査/受領/必要判断/別担当統合を照合する。既存判定1〜3は有効範囲で使い、4/5を呼び戻さない。

### Consequences

- adapter間で同じ意味を保ち、実物改変、現在対象の変更、PR自身のchecker弱体化を負例で検証できる。欠落/未実行/skip/timeout/不明を成功にせず、非適用は理由と適用条件に結び付ける。
- 信頼版の取得と適合、CI実行と記録の接続が必要になる。workflowとrequired設定の具体変更には従来の保護条件を保持する。
- 実行結果の検証はTDD、適用SEC-T、追加前の依存脆弱性確認、用途別最小権限、scriptsと適用src等を含む実分母100%を保つ。mainの80%とsrc対象漏れは未解消の不足であり、閾値/分母の正本を二重定義しない。S1〜S9の既定/例外/report-onlyを新たな一律blockへ変えない。

### Alternatives Rejected

- **席のセンサー結果やPRの設定をそのまま信頼する。** 既存の利用は容易でも、自己弱体化・古いhead・未実行を区別できずFR12を満たさない。
- **CI用とLLM別に同じ判定を実装する。** 各環境へ最適化できるが規則と理由が分岐する。輸送/形式adapterと実行周辺だけを変える。
- **すべてをI/O付きの一関数へまとめる。** 入口は少なくなるが時計・外部取得・再実行が判定へ混ざるため純粋核を保つ。

## ADR-005: 固定版の配布と受け手実物のdriftを照合する

### Context

kitは固定版を配置/比較できるが、AI-DLCセンサー設定と対話は未接続で、root/mainの自己適用保護も異なる。registry/pinの宣言や404だけで現在の導入を判定できない。AUNへの実配布には既存担当・保留・必要判断があり、配布元の成功を受け手の成功へ流用できない。関連はFR1・FR6.3・FR12.3〜12.4・FR13、NFR2・NFR4・NFR8。

### Decision

KitDistributionが配布元の実観測に結び付くDistributionRevisionと、受け手の適用/driftのDistributionAssessmentを所有する。固定版の実内容と許可差分、戻し方を扱い、効果前には必要条件の実観測と停止制御を必須にする。受け手の実内容から比較し、欠落・advisory化・別版・対象範囲変更と不能を区別する。

Shirube自己適用のworkflow_call、対象外ファイル、既存設定・履歴を保持する。AUNの現担当・受領・取り組み・保留と公開判断/head条件を保ち、準備・適用・検証を別々に示す。.codex/.claudeの対応配置を再確認し、未検証配置を成功にしない。driftを自動修正許可にしない。

### Consequences

- 配布版と実物とCI実行版の対応を確認できる。受け手の宣言だけでは成功にならず、部分適用・誤対象・版違いを検出する。
- 固定版ごとに互換性と復旧を検証する必要がある。形式変更は旧新同居と試験された逆向きを持ち、正常値と履歴を保全する。
- AUNは実ファイルと実PRの4項目正負、必須CI不能/自己弱体化、実drift/復旧を別に観測する。非公開原本は権限のある元で照合し、公開Shirubeは架空入力と公開可能な結果だけを持つ。既存kit例外を新センサー・初回導入・保護設定変更へ拡張しない。

### Alternatives Rejected

- **利用先が設定を手作業で維持し、配布元は案内だけを出す。** 利用先の自由度は高いが、Shirubeが版付き設定を配り実driftを検出する今回の要件を満たさない。
- **registry/pinとmanifestの一致で適用済みとする。** 安価でも途中失敗や実設定の弱体化を見落とす。宣言ではなく観測実物を比較する。
- **driftを見つけたら最新へ自動更新する。** 復旧操作は減るが、既存保留と保護対象の許可、版適合の判断を省くため採用しない。

## ADR-006: 操作の停止と同一要求を既存の核へ集める

### Context

正規接続と配布では、人待ち、非進捗、中断、結果不明、再送、競合を同じ意味で扱う必要がある。既存progression-coreには同一要求・照会・非進捗停止の核があるが、実adapterや耐久性は無い。これを別の開発工程へ昇格させず使う必要がある。関連はFR1.3・FR7・FR8.3、NFR4・NFR6・NFR7、R2とS4/S7/S8。

### Decision

SafeOperationControlがOperationAttemptを所有し、必要条件の実結果、現在の実観測、時刻・識別子と要求情報を明示入力として評価する。I/OはNativeAIDLCConnectionやKitDistributionの周辺に置く。核が保存/時計/実行の手段を取得せず、呼出側の周辺が結果を保存・照会して再入力する。用途を正規接続と配布の実際の必要へ限定し、汎用executorや常駐watcherを追加しない。

人待ちは一度通知して停止し、待機中の新しい効果・成果物・後継記録を生産しない。連続非進捗と外部照会は正式な有限上限/予算を守る。効果の送信前から同一要求を保持し、応答不明なら同じ要求を照会し、別内容の同一キーや競合を拒否する。副作用の無い読取に無意味なキーは要求しない。

### Consequences

- 同一内容の効果一回と結果不明時の照会を、正規接続/配布で同じ意味にできる。正当な再開では実対象・設定・証拠・承認を再読し、有効な回答/履歴と未完了範囲を保持する。
- 効果とOperationAttemptの保存・結果照会の対応、競合/中断/復旧と有限予算は実接続の契約と試験が必要。核の存在だけで耐久性や二重効果防止が実証済みとはしない。
- 停止は正しい終端である。必要な人の判断と状態変化が無ければ実行を再開しない。OperationAttemptは正式AI-DLCの段状態や承認の台帳ではない。

### Alternatives Rejected

- **正規接続と配布で個別の再試行/停止規則を作る。** 局所的には簡単でも、同じS7や人待ちの意味が分岐する。既存の具体的な核を使う。
- **progression-coreを第二の開発進行元として起動する。** 既存名に沿った実装は可能でも、正式AI-DLCの状態と段順を重複させるため採用しない。
- **結果不明を失敗として新キーで再送する。** 回復は早く見えるが二重効果を防げないため、照会と同一要求を維持する。

## Unverified Contracts and Preserved Acceptance

最も重要な未検証箇所はADR-003の正式原本/実発行元→公開用記録→CIの接続である。これを解消済みとは記録しない。その他の対象/版接続、同PR設計監査の順序、信頼版CIと配布の対応、停止と適用周辺の契約は[components.mdのContract Design Handoff](components.md#contract-design-handoff)へ集約する。成立しない条件を発見したら、具体差を明らかにして必要な判断へ戻す。

初回は実物に基づく導入状態・不足・適用規格と安全な次操作の実表示を実コードで完成させる。その後の新要求で項目選択→現対象/前提/必要判断の再照合→案内切替を実装し、同じ架空入力の前後結果で増分を証明する。初回の必須案内を削る、既存動作を再実装する、文言だけ変える差では合格にしない。実差が成立しなければ題材をOwnerへ戻す。

初回と追加変更の承認・試験・監査は別の現差分へ対応させる。AUNの実証と全13Mustの必須合否は別に残る。公開repoは架空データのみであり、実データ・秘密・非公開記録を含めない。W-01〜W-03、別DB intentとその保留、採択規格の既定/例外と維持・向上を保持する。設計先行制御の相談を今回の実装範囲へ加えない。
