## この問いで具体化する範囲

初回と追加変更で、Shirube 自身のどの実機能を完成させて継続開発を確かめるかを具体化する。製品の目的や全13項目を決め直す問いではない。

どの題材でも、導入の対話、必要な設定、明示的な開始、AI-DLC による実際の機能変更、必要な試験・CI・独立監査・受領・承認・統合、対象と証拠を対応付けた完了確認を通す。追加変更では、初回の設定・リポジトリ・記録・体制を保持し、新しい変更に必要な判断と検証を改めて行う。前のゴールの合格を次の変更へ流用しない。

表示は LLM との対話を通じて利用者が確認できるものとする。専用の Web 画面、特定の status コマンド名、API の形式、単位の分割や実装順を、この問いで固定しない。具体的な契約・検証コマンド・実装計画は後続で定める。

M-09 の「人が承認する段に対応する READY」を弱める例外は提案しない。見直し役が未設定、実行不能、未実施、対象不一致の状態を合格にせず、必要な正式記録が揃わない状態では進めない。現在の AI-DLC の対象段・設定との接続は後続の設計で明示する。自己生成の READY、未知の見直し役への自動委任、段の設定や保護対象の変更を、この問いの回答から許可されたと推測しない。

## Q1. [製品責任者] 最初のゴールと、その後の追加変更で完成させる実機能は、この組にするか

導入から継続開発までを実物で通す方針は確認済み。ここでは、その中で本当にコードを変更して完成させる、Shirube 自身の小さな機能の題材を決める。架空の別製品や文書だけの変更で、実開発の代わりにしない。

提案する組は次のとおり。

- **最初のゴール**：Shirube 自身の導入状態、必要な設定の不足、適用する規格を、実物から確認して利用者に示す機能を完成させる。例として「設定が揃っている」「設定項目が1つ足りない」「権限不足で確認できない」を区別して、LLM との対話で説明できるようにする（M-01・M-02・M-06・M-07）。その機能変更を、導入・設定・明示開始から AI-DLC の開発と必要な検証・統合まで通して確認する。
- **実際の追加変更のゴール**：同じ機能へ、確認結果に基づく「次に必要な操作」の案内を追加する。例として、不足なら必要な設定を案内し、確認できないなら権限の確認を案内し、準備が揃っていても利用者の明示開始を待つ。AI-DLC が決める次の段や承認条件を独自に変更しない（M-02・M-03・M-07・M-08）。最初のゴールの後に新しい要求として受け付け、同じ規格・監査・試験を保ち、新しい変更の実際の結果で完了を確認する。

この2つは初回・追加変更の実証の題材であり、初版全体の完了条件を置き換えない。M-01〜M-13、4つの機械的な確かめ、AUN への実配布と実際の PR の正例・負例・設定のずれの検証は、すべて必要なまま残す。今回の回答は題材の指定であり、実装計画や保護対象の具体的な変更の承認ではない。

A. この組にする。初回は実物に基づく導入・設定・規格の確認表示、追加変更は同じ機能への次の操作の案内を完成させる。
B. 別の実機能の組にする。Shirube 自身で完成させたい初回の機能と、その後の追加変更を回答に記す。承認済みの必須範囲を変える必要があれば、その差を別に確認する。

## Consolidated Summary Confirmation

- Shirube と AI-DLC の安全な導入、必要な設定の対話、利用者の明示的な開始、AI-DLC に沿った実開発、必要な確認、実際のゴール到達、その後の追加開発までをつなぎます。入口は LLM との対話で、Codex 専用にはしません。既存の設定・ファイル・履歴を保ち、確認できたことは聞き直さず、不足と食い違いだけを聞きます。最初の実証は社内の Codex CLI・Mac・GitHub・GitHub Actions で行います。
- 初回に完成させる実機能は、Shirube 自身の導入状態・設定の不足・適用規格を、実物から確認して示すものです。初回のゴール後、同じ機能へ「次に必要な操作」の案内を実際の追加変更として実装します。両方で、明示開始から必要な開発・検証・統合・完了確認までを通し、新しい変更の実際の結果で確かめます。コマンド名や API は後続で決めます。この2つの題材だけで、全13項目や AUN での受入まで完成したとはしません。
- 採択済みの技術・セキュリティ規格と S1〜S9、実装前に失敗する試験を確かめる TDD、行網羅率100%、適用される SEC-T、依存追加前の脆弱性確認、最小権限を維持します。規格の版・適用対象・証拠・合否を追い、網羅率の対象と分母を明示して、対象を勝手に外して100%にしません。必要な機械の接続と検証の不足を補うことを今回の向上とし、新しい社内規格を勝手に採択しません。
