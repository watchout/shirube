## 既知の回答 — Way of Working

引継ぎ: AI-DLC の作業場と段の中で、1単位を1つの PR とし、前の PR が統合されてから次の単位を作る。設計・実装・監査の記録、CI、作者の受領、作者以外の統合担当を揃える。DB構造・権限・契約・セキュリティに触れる単位は、設計だけの PR を独立監査し、その同じ PR に実装を追加して再び監査する。merge commit を使う。保護対象には必要な公開決定と対象headの承認を確認する。

出典: 既存 `memory/team.md` の Way of Working、P1・P2・P3、今回の承認済み scope M-04/M-09〜M-12。古い「設計監査は行わない」「R2以上だけ監査」の文を、後の具体的条件を省く根拠にはしない。作者自身の監査依頼と既存の受付・受領手順は保持する。今回の回答として新しい `[Answer]:` は作らない。

## 既知の回答 — Testing Posture

引継ぎ: TDD（実装の前に失敗する試験を作って失敗を確かめる方法）、Node 組込みの node:test、行の網羅率100%。適用される安全の試験、依存導入前の脆弱性確認、最小権限を保つ。TDDを別々の2本のPRにする必要はなく、現行の1単位1PRに従って記録する。

出典: 既存 `memory/team.md` の Q3・Methodology/Ordering、P4・P7、scope M-06。採択100%に対し、作業場の CI は閾値なし、固定版 main は80%という差がある。未測定の実測値を埋めず、後続の試験・CIで解消と検証を行う。
